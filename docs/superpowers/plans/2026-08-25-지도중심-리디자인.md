# 지도 중심 리디자인 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** SEED Design 색상 토큰을 Seline 스타일(따뜻한 시안 배경 + 청록 단색 악센트)로 전면 오버라이드하고, 지역 결과 화면(단지 목록+지도)을 사이드바+지도 그리드 레이아웃으로 바꾸며, 등기부등본 문진을 제거한다.

**Architecture:** SEED의 상호작용 컴포넌트(체크박스·슬라이더·텍스트필드)는 그대로 두고, `src/seed-brand.css`의 기존 브랜드 토큰 오버라이드 패턴을 의미 계층 전체로 확장한다. 레이아웃은 `App.tsx`의 기존 조건부 렌더링 로직을 건드리지 않고 CSS 그리드 래퍼만 씌운다. 지도 마커는 `ComplexMap.tsx`의 기존 그룹핑·이스케이프·클린업 로직 위에 커스텀 HTML 마커(가격 항상 표시)를 얹는다.

**Tech Stack:** 기존 React 19 + TypeScript(strict) + Vitest 스택. 새 의존성: `pretendard`(로컬 웹폰트).

## Global Constraints

- 단일 "적정가"를 절대 내지 않는다 — 지도 마커도 범위(`minPrice`~`maxPrice`)로만 표기한다.
- 재무정보는 브라우저를 벗어나지 않는다 — Pretendard는 반드시 로컬 번들(`pretendard` npm 패키지)로 싣는다. 외부 CDN `<link>`나 `@import url(https://...)`는 금지 — `src/no-network.test.ts`가 `.css` 파일도 스캔하므로 위반 시 기존 테스트가 잡는다.
- SEED Design의 상호작용 컴포넌트(`seed-design/ui/checkbox`, `seed-design/ui/slider`, `seed-design/ui/text-field`, `seed-design/ui/action-button`)는 재구현하지 않는다 — 색상만 CSS 변수 오버라이드로 바꾼다.
- 예산 계산(프로필 입력 → 실구매 가능 가격) 흐름의 조건부 렌더링 로직은 손대지 않는다 — 색상·타이포만 바뀐다.
- `ComplexMap.tsx`의 기존 안전장치(`complexKey` 단위 그룹핑, `escapeHtml`, 언마운트/재렌더 시 마커·리스너 정리, 로드 실패 처리)는 유지·확장한다 — 다시 쓰지 않는다.
- 시/군/구 필수·동 옵션(기본값 "전체" = 구 전체 결과)이라는 `RegionSelect`의 기존 동작은 그대로 유지한다.
- 인쇄(print) 동작은 깨지면 안 된다 — 새로 추가하는 인터랙티브 요소 중 인쇄에서 숨겨야 할 게 있으면 `PRINT_HIDDEN_SELECTORS`(`src/print/hiddenInPrint.ts`)와 `src/styles.css`의 `@media print` 블록에 동기화 반영하고, `scripts/printCss.test.ts`가 계속 통과해야 한다.
- 각 태스크 후 `npx vitest run`과 `npm run typecheck`가 깨끗해야 한다.
- 참고 스펙: `docs/superpowers/specs/2026-08-25-지도중심-리디자인-design.md`

- [ ] **Step 2: 로컬 CSS를 import한다**


- [ ] **Step 3: `body`의 폰트 패밀리를 바꾼다**

`src/styles.css`의 `body` 규칙(파일 최상단 근처)을 찾아 바꾼다:

```css
body {
  margin: 0;
  font-family: "Pretendard", ui-sans-serif, system-ui, -apple-system, "Segoe UI", "Noto Sans KR", sans-serif;
  line-height: 1.6;
}
```

- [ ] **Step 3.5: Seline 사이즈 스케일에 맞춰 주요 텍스트 크기를 재매핑한다**

Seline 스케일: caption 10px, body-lg 16px, subheading 20px, heading-sm 32px, display 52px. 이 앱의 기존
정보 위계(무엇이 가장 커야 하는지)는 그대로 두고, 숫자 값만 이 스케일에 맞춘다. `src/styles.css`에서
다음을 찾아 조정한다:

```bash
grep -n "font-size" src/styles.css
```

- 가장 중요한 숫자(`.affordable-price` — 실구매 가능 가격, 현재 `2rem`≈32px)는 Seline의
  `heading-sm`(32px)에 이미 가깝다 — 그대로 두거나 `2rem`을 유지한다.
- 제목(`h1`/`h2` 등)이 있다면 `display`(52px, 페이지 최상단 제목 정도)나 `heading-sm`(32px, 섹션
  제목)에 맞춘다 — 지금 이 앱에 52px급 제목이 있는지 먼저 확인하고, 없으면 무리해서 만들지 않는다
  (YAGNI — 없는 위계를 새로 만들지 않는다).
- 본문(`body`의 기본 크기, 라벨 등)은 `body-lg`(16px)에 맞춘다.
- 힌트·캡션류(`.hint`, `.subtitle`, `.disclaimer` 등 지금 `0.8125rem`~`0.875rem`대)는 Seline의
  `caption`(10px)까지 줄이면 이 앱에서는 너무 작아 가독성이 떨어질 수 있다 — 무리하게 10px에
  맞추지 않고, 지금 값과 `body-lg` 사이 어딘가(예: `0.8125rem`≈13px 유지)로 절충한다. 정보 위계
  유지가 스케일 숫자 일치보다 우선이다.

로컬 서버(`npm run dev:full`)로 크기 변경 후에도 정보 위계(무엇이 가장 크고 무엇이 가장 작은지)가
지금과 같은지 확인한다.

- [ ] **Step 5: 로컬 서버로 폰트가 실제로 적용됐는지 확인한다**

`npm run dev:full`로 띄우고(이미 켜져 있으면 재사용), 브라우저 개발자 도구에서 `body`의 computed `font-family`가 Pretendard를 포함하는지, 네트워크 탭에 `oapi.map.naver.com`·`apis.data.go.kr`·`naveropenapi`류 외에 폰트 관련 외부 요청이 없는지(전부 `localhost`에서만 오는지) 확인한다.

```typescript
 * "brand" 계열이 아니라서 그 정규식에 잡히지 않는다.
 */

/** WCAG 상대 휘도 → 대비율 계산. 순수 함수라 이 파일 안에 직접 둔다. */
function hexToRgb(hex: string): [number, number, number] {
  const n = Number.parseInt(hex.replace("#", ""), 16);
  return [(n >> 16) & 255, (n >> 8) & 255, n & 255];
}

function relativeLuminance([r, g, b]: [number, number, number]): number {
  const f = (c: number) => {
    const v = c / 255;
    return v <= 0.03928 ? v / 12.92 : ((v + 0.055) / 1.055) ** 2.4;
  };
  return 0.2126 * f(r) + 0.7152 * f(g) + 0.0722 * f(b);
}

function contrastRatio(hexA: string, hexB: string): number {
  const lA = relativeLuminance(hexToRgb(hexA));
  const lB = relativeLuminance(hexToRgb(hexB));
  const [lighter, darker] = lA > lB ? [lA, lB] : [lB, lA];
  return (lighter + 0.05) / (darker + 0.05);
}

describe("등급색 대비율 — 흰 배경(#ffffff), 본문 크기 기준 4.5:1", () => {
  it("safe(#15803d)", () => {
    expect(contrastRatio("#15803d", "#ffffff")).toBeGreaterThanOrEqual(4.5);
  });
  it("caution(#b45309)", () => {
    expect(contrastRatio("#b45309", "#ffffff")).toBeGreaterThanOrEqual(4.5);
  });
  it("danger(#b91c1c)", () => {
    expect(contrastRatio("#b91c1c", "#ffffff")).toBeGreaterThanOrEqual(4.5);
  });
});
```

```typescript
/**
 * 지금 지도에 그려지는 단지들(대표 평형 minPrice 기준) 중 가격 3분위
 * 구간을 매긴다. 단지가 3개 미만이면 전부 중간 톤 하나로 통일한다.
 * 절대 가격대를 하드코딩하지 않는다 — 지역마다 시세가 달라 상대적인
 * 기준이어야 의미가 있다(부모 스펙 §1.4).
 */
type PriceTier = "low" | "mid" | "high";

function priceTiers(groups: Array<{ complexKey: string; representative: ComplexUnit }>): Map<string, PriceTier> {
  if (groups.length < 3) {
    return new Map(groups.map((g) => [g.complexKey, "mid"]));
  }
  const sorted = [...groups].sort((a, b) => a.representative.minPrice - b.representative.minPrice);
  const third = Math.ceil(sorted.length / 3);
  const tiers = new Map<string, PriceTier>();
  sorted.forEach((g, i) => {
    const tier: PriceTier = i < third ? "low" : i < third * 2 ? "mid" : "high";
    tiers.set(g.complexKey, tier);
  });
  return tiers;
}
```
