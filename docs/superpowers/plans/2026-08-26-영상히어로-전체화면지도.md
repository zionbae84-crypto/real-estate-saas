# 영상 히어로 + 전체화면 지도 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax.

**Goal:** 세로로 긴 한 페이지를 두 화면으로 나눈다 — 영상 배경 위 입력 화면, 그리고 전체화면 지도(좌측 사이드바 + 지도). 팔레트는 배경 영상에서 뽑은 청회색 + 황동으로 바꾼다.

**Architecture:** 계산 로직(`useAffordability`, `buildComplexList`, `useProfileForm`, `useRegionComplexes`, `useComplexCoordinates`)은 손대지 않는다. `App.tsx`에 `phase` 상태를 하나 더해 기존 컴포넌트들을 두 화면으로 재배치하고, 스타일을 새 팔레트로 갈아입힌다.

**Tech Stack:** 기존 React 19 + TypeScript(strict) + Vitest + SEED Design + Naver Maps. 새로 더하는 것: 한글 명조 웹폰트(로컬 번들), `public/media/`의 배경 영상.

**참고 스펙:** `docs/superpowers/specs/2026-08-26-영상히어로-전체화면지도-design.md` — 팔레트 값, 두 화면의 구조, 프로토타입에서 겪은 버그 두 가지가 전부 거기 있다. 각 태스크는 이 스펙을 먼저 읽는다.

## Global Constraints

- 단일 "적정가"를 절대 내지 않는다 — 마커·목록·상세 어디서도 범위로만.
- 재무정보는 브라우저를 벗어나지 않는다 — 영상·폰트 전부 로컬 번들. `src/no-network.test.ts`의 예외 파일은 정확히 둘로 유지.
- SEED 상호작용 컴포넌트(체크박스·슬라이더·텍스트필드·액션버튼)는 재구현하지 않는다. 색만 CSS 변수로.
- 계산 로직은 손대지 않는다. 이번 작업은 **어디에 무엇을 그리는가**만 바꾼다.
- `App.tsx` 조건부 렌더링에는 여섯 번 반복된 버그 이력이 있다(한 축의 "모름/비어 있음"이 다른 축의 기본값으로 흡수됨). 조건을 옮길 때 각 빈 상태가 자기 원인을 말하는지 확인한다.
- 인쇄가 깨지면 안 된다. `PRINT_HIDDEN_SELECTORS` ↔ `@media print` 동기화(`scripts/printCss.test.ts`), `MUST_SURVIVE_PRINT_CLASSES` 내용은 잘리지 않아야 한다. **`overflow`/`max-height`를 건 요소는 반드시 `@media print`에서 푼다.**
- 시/군/구 필수, 동은 옵션(기본값 "전체").
- 각 태스크 후 `npx vitest run`과 `npm run typecheck`가 깨끗해야 한다.

## Task 1: 팔레트를 영상에서 뽑은 값으로 교체한다

**Files:** `src/seed-brand.css`, `src/styles.css`, `scripts/seed-semantic-tokens.test.ts`

**Produces:** 스펙 §1의 모든 토큰. Task 3~5가 이 이름으로 쓴다.

- [ ] **Step 1: 스펙 §1의 표를 그대로 옮긴다**

`src/seed-brand.css`의 기존 오버라이드 블록(같은 셀렉터 안 — 이 파일은 명시도 함정이 있어 새 블록을 만들면 조용히 진다) 안에서 SEED 의미 토큰을 새 값으로 다시 가리킨다. 어두운 면 세트와 밝은 면 세트를 둘 다 정의한다.

기존 Seline 값(`#fafaf9`, `#3ba6f1` 등)은 전부 교체된다. `--seed-color-bg-tier-high` 같은 지도 마커용 토큰은 Task 4에서 뜻이 바뀌므로 여기서는 남겨 둔다.

- [ ] **Step 2: 대비율을 직접 계산해 테스트에 박는다**

`scripts/seed-semantic-tokens.test.ts`의 기존 헬퍼(`hexToRgb`/`relativeLuminance`/`contrastRatio`)를 재사용한다. 새 값 전부에 대해:
- 밝은 면 본문(`--on-sheet` on `--sheet`, `--sheet-2`): ≥ 4.5:1
- 밝은 면 보조(`--on-sheet-soft` on `--sheet-2`): ≥ 4.5:1
- 밝은 면 금액(`--brass-ink` on `--sheet-2`): ≥ 4.5:1
- 어두운 면 본문(`--paper` on `--ink`, `--ink-2`): ≥ 4.5:1
- 어두운 면 금액(`--brass-lift` on `--ink-2`): ≥ 4.5:1
- 태그 색 조합 둘: ≥ 4.5:1

**계산 결과를 보고서에 실제 숫자로 적는다.** 4.5:1을 못 넘는 조합이 있으면 그 값만 스펙에서 벗어나 조정하고, 무엇을 왜 바꿨는지 보고한다 — 임의로 넘기지 않는다.

- [ ] **Step 3: `src/styles.css`의 남은 하드코딩 색을 새 토큰으로 옮긴다**

```bash
grep -noE '#[0-9a-fA-F]{3,6}|rgba?\([^)]+\)' src/styles.css
```
주석 안의 설명용 hex는 그대로 두되, 그 주석이 말하는 수치가 이제 틀렸으면 갱신한다(직전 개편에서 브랜드 색이 바뀌었을 때 실측 수치를 남긴 주석이 여럿 있다).

- [ ] **Step 4: 검증 + 커밋**

`npx vitest run && npm run typecheck`. 로컬 서버로 화면을 열어 색이 실제로 바뀌었는지 눈으로 확인한다(방법은 아래 "환경 메모" 참고).

```bash
git commit -m "feat: 팔레트를 배경 영상에서 뽑은 청회색·황동으로 바꾼다"
```

## Task 3: 화면 1 — 영상 위 입력 화면

**Files:** `src/App.tsx`, 새 `src/components/EntryScreen.tsx`, `src/styles.css`

**Consumes:** Task 1의 토큰, Task 2의 명조체·영상
**Produces:** `phase` 상태 (`"입력" | "결과"`), `EntryScreen` 컴포넌트

- [ ] **Step 1: 스펙 §3을 읽고 현재 `App.tsx`의 해당 부분을 파악한다**

`PurchaseTypeSelect`, `ProfileForm`, `RegionSelect`가 지금 어떻게 렌더되는지, 각각의 prop과 조건을 정확히 읽는다. **이 컴포넌트들의 로직·prop은 바꾸지 않는다** — 감싸는 자리와 스타일만 바뀐다.

- [ ] **Step 2: `phase` 상태를 더한다**

`App.tsx`에 `const [phase, setPhase] = useState<"입력" | "결과">("입력")`. 지역 조회가 성공하면(`handleRegionSelect` 안에서, 혹은 조회 성공을 보는 자리에서) `"결과"`로 넘어간다. "조건 다시 넣기"가 `"입력"`으로 되돌린다.

**주의**: 되돌아갔을 때 이미 입력한 값이 남아 있어야 한다(`useProfileForm`의 상태는 그대로 유지). 새로 조회하지 않고 그냥 화면만 돌아가는 것이므로, 기존 조회 결과도 유지된다.

- [ ] **Step 3: `EntryScreen`을 만든다**

스펙 §3의 구조·스크림 값·"상자가 아니라 밑줄" 원칙 그대로. `PurchaseTypeSelect`/`ProfileForm`/`RegionSelect`를 자식으로 받거나 직접 렌더한다(어느 쪽이 기존 prop 배선을 덜 흔드는지 보고 판단).

⚠ 입력 영역이 세로로 넘치면 상단이 잘린다 — `justify-content: safe center` + `overflow-y: auto`로 막는다. 프로토타입에서 실제로 겪었다.

`<video autoplay muted loop playsinline poster="/media/cheongdam-han-river-hero.png">`. 자동재생이 막히면 poster가 그대로 보이므로 별도 처리는 필요 없다.

`prefers-reduced-motion: reduce`일 때는 영상을 재생하지 않고 poster만 보여준다.

- [ ] **Step 4: 기존 테스트를 고친다**

`src/App.test.tsx`의 여러 테스트가 "폼을 채우면 결과가 같은 화면에 나온다"를 전제한다. 이제 화면이 갈리므로 **조회 버튼을 눌러 결과 화면으로 넘어가는 단계**가 추가된다. 기존 헬퍼(`fillProfile`, `chooseRegion` 등 — 이 파일은 describe마다 자기 헬퍼를 새로 정의하는 관례다)를 새 흐름에 맞게 고친다.

**테스트가 검증하는 사실 자체를 바꾸지 않는다** — 도달 경로만 바뀐다. 어떤 테스트를 왜 고쳤는지 보고한다.

- [ ] **Step 5: 검증 + 커밋**

로컬에서 실제로 영상이 재생되고 입력이 되는지 확인. 전체 스위트 + 타입체크.

## Task 4: 화면 2 — 전체화면 셸(상단바 + 사이드바 + 지도)

**Files:** `src/App.tsx`, 새 `src/components/ResultShell.tsx`(또는 유사), `src/components/ComplexMap.tsx`, `src/styles.css`, `src/print/hiddenInPrint.ts`

**Consumes:** Task 3의 `phase`
**Produces:** 전체화면 결과 레이아웃

- [ ] **Step 1: 스펙 §4를 읽는다. 특히 경고 두 개.**

⚠ `.stage`에 `grid-template-rows: minmax(0, 1fr)`를 **반드시** 준다. `auto`로 두면 지도(자식이 전부 absolute라 내재 높이 0)가 높이를 못 받아 타일이 안 뜬다.

⚠ 네이버 SDK가 지도 컨테이너에 `position: relative`를 **인라인으로 덮어써서** `inset: 0`이 무력화된다. 컨테이너에 `width: 100%; height: 100%`를 함께 준다.

둘 다 프로토타입에서 실제로 겪고 고친 버그다. 구현 후 지도 컨테이너의 실제 렌더 크기를 `getBoundingClientRect`로 확인해서 0이 아닌지 보고한다.

- [ ] **Step 2: 셸을 만든다**

스펙 §4의 구조. 상단바 요약 항목, 사이드바(헤더 + 필터 + 목록), 지도. `ComplexList`와 `ComplexMap`을 이 안으로 옮긴다 — **두 컴포넌트의 로직과 prop은 그대로**, 감싸는 자리만 바뀐다.

`body { overflow: hidden }`은 결과 화면일 때만 걸린다(입력 화면은 넘칠 수 있으므로).

- [ ] **Step 3: 마커 색의 뜻을 바꾼다**

지금 `ComplexMap.tsx`의 `priceTiers`는 가격 3분위다. 이것을 **부담 수준 2분류**(대출 없이 / 대출 필요)로 바꾼다. 판정 근거는 목록 행이 이미 쓰는 값과 **같은 출처**여야 한다 — `buildComplexList`가 내는 청크(`withinSafe`/`unverified`/`beyondSafe`)나 각 항목이 이미 들고 있는 값을 쓴다. 지도가 목록과 다른 계산을 새로 하면 두 화면이 다른 말을 하게 된다(이 저장소가 여섯 번 겪은 버그 형태).

`priceTiers`의 기존 테스트(경계 n=0..4, 마커에 클래스가 실제로 닿는지)를 새 분류에 맞게 고친다. **마커 라벨의 `escapeHtml` 적용은 그대로 유지한다** — 이 파일은 앱에서 유일한 raw HTML 주입 지점이고 의도된 것이다.

지도 좌측 하단에 범례를 넣는다.

- [ ] **Step 4: 목록 ↔ 마커 양방향 연결**

행 클릭 → 지도 이동 + 마커 강조. 마커 클릭 → 행 선택 + 목록 스크롤. 선택 상태는 한 곳에서 관리한다(두 벌로 관리하면 어긋난다).

- [ ] **Step 5: 인쇄에서 레이아웃을 푼다**

`position: fixed`, 사이드바 스크롤, `body overflow: hidden`을 전부 `@media print`에서 해제하고 지금과 같은 세로 문서로 흐르게 한다. 지도는 인쇄에서 숨긴다(이미 그렇다). 새로 만든 스크롤 영역 전부에 같은 처리.

`PRINT_HIDDEN_SELECTORS`와 `@media print`를 동기화하고 `scripts/printCss.test.ts`가 통과하는지 확인한다.

- [ ] **Step 6: 검증 + 커밋**

지도 타일이 실제로 뜨는지, 마커가 부담 수준대로 색이 갈리는지, 인쇄 미리보기에서 목록이 안 잘리는지 확인. 전체 스위트 + 타입체크.

```bash
git commit -m "feat: 결과 화면을 전체화면 사이드바+지도로 바꾼다"
```

## Task 5: 패널 — 예산 상세 / 단지 상세 / 진단 종합

**Files:** `src/App.tsx`, `src/components/`(새 패널), `src/styles.css`, `src/print/hiddenInPrint.ts`

**Consumes:** Task 4의 셸

- [ ] **Step 1: 예산 상세 패널**

상단바의 "한도 3억 2,090만원"을 누르면 펼쳐지는 패널. 안에 지금의 `BudgetResult`(대출 한도 4종, 부대비용, 정책대출), `PriceSlider`, `SafeLine`, `AssumptionLine`이 들어간다. **이 컴포넌트들의 로직·prop은 그대로.**

닫기 가능해야 하고, `Esc`로도 닫힌다. 열려 있을 때 지도 조작을 막지 않는 편이 낫다(오버레이 패널로, 화면 전체를 덮지 않게).

- [ ] **Step 2: 단지 상세 — 사이드바 전환**

행을 누르면 사이드바가 목록에서 `ComplexDetail`로 바뀐다. "← 목록으로" 버튼으로 되돌아간다. `ComplexDetail`의 prop과 로직은 그대로 — `detail` 계산(`selectedUnit`, `residentialProfile` 조건)도 그대로다.

⚠ 지금 `App.tsx`는 상세가 열리면 목록 전체를 대신 그린다. 그 조건을 사이드바 안으로 옮기되 **조건식 자체는 바꾸지 않는다.**

- [ ] **Step 3: 진단 종합을 상세 안으로**

`DiagnosisSummary`를 `ComplexDetail` 아래로 옮긴다. 네 축 중 권리분석은 영구히 `null`(등기부 문진이 제거됐다)이고, 나머지 세 축의 조건도 그대로다. **`rights={null}`을 계속 넘긴다.**

- [ ] **Step 4: 인쇄 버튼을 상단바로**

기존 `.print-button`의 동작은 그대로, 자리만 상단바로. 인쇄 시 버튼 자신은 숨긴다(이미 그렇다).

- [ ] **Step 5: 전체 흐름 확인 + 커밋**

입력 → 조회 → 목록 → 단지 선택 → 상세 → 진단 종합 → 인쇄까지 한 번에 밟아 본다. 각 단계에서 빈 상태(데이터 없음 / 예산 부족 / 동 좁힘 / 좌표 실패 / SDK 실패)가 여전히 **자기 원인**을 말하는지 확인한다.

```bash
git commit -m "feat: 예산 상세·단지 상세·진단 종합을 새 구조에 배치한다"
```

## 환경 메모 (모든 태스크 공통)

- **`preview_start`의 `budget-app`/`budget-app-full` 이름은 이 워크트리가 아니라 부모 저장소 디렉터리에서 서버를 띄운다** — 조용히 옛 코드를 서빙한다. Bash로 이 워크트리에서 직접 `npm run dev:full`을 띄우고, 서빙되는 내용이 이 워크트리 것인지 확인한다(바꾼 파일을 curl 해 보거나 `lsof`로 프로세스 cwd 확인).
- **스크린샷이 이 환경에서 자주 빈 화면으로 온다.** `getComputedStyle`/DOM 질의/`get_page_text`로 대신 확인하고, **어느 방법으로 확인했는지 보고서에 명시한다** — 보지 않은 것을 본 것처럼 적지 않는다.
- `.env`(실제 API 키)는 이미 워크트리에 복사돼 있고 gitignore된다. 커밋하지 않는다.
- 네이버지도 SDK는 등록된 도메인에서만 뜬다. 포트 4173이 등록돼 있다.
