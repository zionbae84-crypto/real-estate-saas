# 지도 중심 리디자인 — 색상·타이포·레이아웃 개편

> 이 스펙은 사용자가 요청한 4가지 중 ②번(디자인 전면 개편 + 지도 중심 구조)만 다룬다.
> ①번(오피스텔 데이터 연동), ③번(카피 축소·톤 변경)은 각각 별도 스펙으로 이후 진행한다.

## 배경과 목표

지금 앱은 위자드형 세로 1단 흐름(예산 입력 → 지역 선택 → 단지 목록 → 지도)이고, 색상·타이포는 SEED
Design(토스 내부 디자인 시스템)을 그대로 쓴다. 사용자는 이 인상이 "서비스로 쓰기엔 엉망"이라 느꼈고,
두 가지를 요청했다:

1. 첨부한 Seline 스타일 가이드(따뜻한 시안 배경 + 청록 단색 악센트, Pretendard급 기하학적 산세리프,
   필 모양 버튼, 헤어라인 카드)로 전체 비주얼을 바꾼다.
2. 지역 선택 이후의 "단지 목록 + 지도" 부분을 호갱노노(hogangnono.com)처럼 지도 중심(사이드바+지도)
   레이아웃으로 바꾼다.

브레인스토밍으로 확정한 범위와 원칙은 아래와 같다.

## Global Constraints (이번 스펙이 절대 깨면 안 되는 것)

- **예산 계산은 그대로 1단계다.** 지금의 프로필 입력 → 실구매 가능 가격 계산 흐름(컴포넌트 순서·조건부
  렌더링 로직)은 손대지 않는다. 이번 스펙은 그 화면의 **색상·타이포만** 바꾼다.
- **단일 "적정가"를 절대 내지 않는다.** 지도 마커도 예외가 아니다 — 항상 범위(`minPrice`~`maxPrice`)로
  표기한다. 이 원칙은 오늘 세션 내내 여러 번 검증·강조된 것이라 되돌릴 수 없다.
- **재무정보는 브라우저를 벗어나지 않는다.** 새 폰트(Pretendard)는 반드시 **로컬 번들**로 실어야 한다 —
  Google Fonts 등 외부 CDN `<link>`나 `@import url(https://...)`는 `src/no-network.test.ts`의 가드를
  위반한다. `pretendard` npm 패키지(정적 woff2 파일 포함)를 쓴다.
- **SEED Design의 상호작용 컴포넌트는 그대로 둔다.** `seed-design/ui/checkbox`(ProfileForm),
  `seed-design/ui/slider`(PriceSlider), `seed-design/ui/text-field`(MoneyInput)는 이미 검증된 벤더
  버그 우회 코드를 포함하고 있다 — 재구현하지 않는다. **색상만** SEED CSS 변수 오버라이드로 Seline
  값으로 바꾼다. `seed-design/ui/action-button`(ErrorBoundary)도 같은 이유로 유지한다.
- **`ComplexMap.tsx`의 기존 안전장치는 유지·확장한다** — `complexKey` 단위 마커 그룹핑(단지×평형이
  아니라 단지 단위), `escapeHtml`을 통한 XSS 방지, 언마운트/재렌더 시 마커·리스너 정리, 로드 실패
  상태 처리. 마커에 가격 라벨을 추가하는 건 이 로직 위에 얹는 확장이지, 다시 쓰는 게 아니다.
- **아래쪽 세션(진단 종합·인쇄하기)의 구조는 그대로 둔다.** 지금처럼 세로로 이어지는 구조를 유지하고,
  색상·타이포그래피만 Seline으로 바꾼다. (등기부등본 문진은 아래 §3.4에서 별도로 다룬다 — 이번 스펙에서
  제거된다.)
- **인쇄(print) 동작은 깨지면 안 된다.** `src/print/hiddenInPrint.ts`의 `PRINT_HIDDEN_SELECTORS`와
  `src/styles.css`의 `@media print` 블록이 `scripts/printCss.test.ts`로 동기화 검증되고 있다 — 새로
  추가하는 요소(사이드바의 인터랙티브 컨트롤 등) 중 인쇄에서 숨겨야 할 게 있으면 이 목록에 반영한다.
- **오피스텔 필터 UI는 자리만 남긴다.** 사이드바에 향후 확장 지점을 두되, 이번 스펙에서 실제 필터
  기능은 구현하지 않는다(별도 스펙).
- **시/군/구는 필수, 동은 옵션이라는 지금 동작을 그대로 유지한다.** `RegionSelect.tsx`는 이미 광역단체
  +자치구까지만 필수로 받고("행정동은 여기서 고르지 않는다" — 국토부 API가 동 단위 파라미터를
  안 받기 때문), 동은 결과가 뜬 뒤 "행정동으로 좁히기" 필터(기본값 "전체")로만 고른다. 동을 안
  고르면 구 단위 전체 결과가 나온다 — 지금도 이렇게 동작한다. 사이드바+지도로 레이아웃을 바꾸면서
  이 동작을 실수로 "동을 먼저 골라야 결과가 뜬다"로 바꾸지 않는다. 지도도 마찬가지로, 동을 좁히지
  않은 기본 상태에서는 구 전체의 단지가 지도에 뜬다(지금 `dongFilteredUnits`가 이미 이 로직이다).

## 1. 색상 시스템

### 1.1 메커니즘: SEED 토큰 오버라이드 확장

`src/seed-brand.css`가 이미 이 패턴을 쓰고 있다 — SEED의 브랜드 토큰(`--seed-color-bg-brand-solid`
등)을 자체 팔레트로 가리켜서 당근 주황을 파랑으로 바꿨다. 이번 스펙은 **같은 패턴을 의미 계층
전체로 확장**한다: 배경·표면·테두리·본문·제목 토큰까지 Seline 팔레트로 다시 가리킨다.

- `src/seed-brand.css`의 셀렉터(`:root, :root[data-seed-color-mode="system"][data-seed-user-color-scheme="light"], :root[data-seed-color-mode="light-only"], :root [data-seed-color-mode="light-only"]`)를 그대로 재사용한다 — `scripts/seed-brand-tokens.test.ts`가 이미 이 셀렉터 짝을 검증하고 있다.
- `src/styles.css`에 하드코딩된 `#666`류 회색(현재 다수 발견됨)은 전부 새 CSS 커스텀 프로퍼티로
  옮긴다.

### 1.2 Seline 팔레트 → 앱 토큰

| Seline 토큰 | 값 | 이 앱에서의 역할 |
|---|---|---|
| `--color-stone-canvas` | `#fafaf9` | 페이지 배경 (`body`) |
| `--color-pure-white` | `#ffffff` | 카드·인풋 표면 |
| `--color-stone-border` | `#e8e6e5` | `--border` (기존 이름 유지, 구조적 헤어라인) |
| `--color-stone-muted` | `#d6d3d1` | 보조 테두리, 장식적 구분선 |
| `--color-ash-gray` | `#a8a29e` | 아이콘 스트로크, 비활성 텍스트 |
| `--color-warm-gray` | `#78716c` | 본문·보조 텍스트 (`.hint`, `.subtitle` 등 기존 `#666` 자리) |
| `--color-ink-black` | `#0c0a09` | 제목, 강조 텍스트 |
| `--color-cyan-signal` | `#3ba6f1` | 주요 액션(버튼 채움), 링크 |
| `--color-cyan-edge` | `#3398e1` | 아웃라인 액션, 강조 텍스트 |
| `--color-sky-wash` | `#c1e1f7` | 인라인 하이라이트 배경 |

SEED 매핑 (`seed-brand.css` 확장):

```css
--seed-color-bg-brand-solid: /* cyan-signal */;
--seed-color-bg-canvas: /* stone-canvas — SEED에 대응 토큰 있는지 확인 후 매핑 */;
--seed-color-fg-neutral: /* ink-black */;
--seed-color-fg-neutral-muted: /* warm-gray */;
--seed-color-stroke-neutral-weak: /* stone-border, 기존 --border가 가리킴 */;
```

(정확한 SEED 토큰 이름은 구현 시 `@seed-design/css/base.css`를 읽어 확정한다 — `seed-brand.css`가
이미 이런 확인을 거친 전례가 있다.)

### 1.3 필수 예외 ① — 안전/주의/위험 등급색

기존 `--safe`/`--caution`/`--danger`는 SEED의 `-fg-positive-contrast` 등에서 왔다. SEED를 걷어내는
게 아니라 **CSS 변수 값만 바꾸는** 것이므로, 이 세 토큰이 실제로 가리키는 hex 값을 Seline 톤에 맞는
새 초록/호박/빨강으로 다시 정의한다.

- 기존 코드 주석이 밝힌 실측 기준(흰 배경, 본문 크기, 4.5:1 이상 — safe 3.96:1이던 실패 사례가 있었음)을
  그대로 다시 적용한다. `-contrast` 단계에 해당하는 진한 값을 고른다.
- 배지·텍스트 두 용도 모두에서 세 등급이 서로 다른 색으로 구분되는지 확인한다.
- 구현 시 후보 값(스톤 웜톤과 어울리는 톤)을 고르고 대비율을 직접 계산해 문서화한다 — 임의로
  정하지 않는다.

### 1.4 필수 예외 ② — 지도 가격 마커

지도 위 마커는 청록 단색 원칙의 예외다. 가격 구간별로 파랑 계열 2~3단계를 쓴다(호갱노노의 다색보다는
절제된 톤 — 청록 신호색 계열 안에서 명도 단계만 다르게).

- 단계 기준: **현재 지도에 그려지는 단지들(그룹핑 후) 중 대표 평형 가격의 최저값을 3분위로 나눈다**
  (하위 1/3, 중위 1/3, 상위 1/3 — 지역마다 상대적인 기준이라 절대 가격대를 하드코딩하지 않는다).
  단지가 3개 미만이면 전부 중간 톤 하나로 통일한다(구간 나누기가 무의미하므로).
- 색만으로 뜻을 전달하지 않는다(기존 `.owned-home-field` 주석의 원칙과 같다) — 가격 숫자 자체가
  이미 마커에 적혀 있으므로 색은 시각적 스캔을 돕는 보조 신호일 뿐이다.

## 2. 타이포그래피

- **Pretendard 하나로 통일**, 로컬 번들(`pretendard` npm 패키지의 정적 웹폰트).
- Seline의 무게 단계를 그대로 따른다 — 제목 400(굵게 만들지 않는다), 본문 400/500/600.
- Seline 사이즈 스케일(52/32/20/16/14/10px)을 이 앱의 기존 텍스트 크기(예: `.affordable-price`의
  2rem 등)에 맞춰 재매핑한다 — 기존 정보 위계(무엇이 가장 커야 하는지)는 유지하되 숫자 값만 Seline
  스케일에 맞춘다.
- `body`의 `font-family`를 `"Pretendard", ui-sans-serif, system-ui, ...`로 바꾼다.

## 3. 레이아웃 — 지역 결과 화면(사이드바 + 지도)

### 3.1 범위

이 구조 변경은 **지역 선택 이후, 단지 목록과 지도가 있는 블록에만** 적용된다. 그 앞(예산 계산)과 뒤
(진단 종합·등기부등본 문진·인쇄하기)는 색상만 바뀌고 세로 1단 구조를 유지한다.

### 3.2 구조

```
┌───────────────────────────────────────────────┐
│  [행정동 좁히기]                                │
│  ┌─────────────────┐  ┌──────────────────────┐ │
│  │ 사이드바          │  │ 지도                  │ │
│  │ (단지 목록,        │  │ (가격 마커,            │ │
│  │  compact 카드,     │  │  ComplexMap 확장)      │ │
│  │  스크롤)           │  │                        │ │
│  └─────────────────┘  └──────────────────────┘ │
└───────────────────────────────────────────────┘
```

- 넓은 화면: 좌측 사이드바(고정 폭 320px, 내부 스크롤) + 우측 지도(나머지 폭 전체, 예: 높이
  600px 고정) 그리드.
- **좁은 화면(768px 미만)**: 사이드바(단지 목록)를 지도 위에 세로로 쌓는다 — 지도 먼저, 목록은
  그 아래로. 지금 이 저장소에는 반응형 브레이크포인트가 전혀 없어(전체 `styles.css`에 `prefers-
  reduced-motion` 외 미디어 쿼리 없음) 이번이 첫 도입이다. 768px는 흔한 태블릿 기준점이고, 이
  하나만 추가해 복잡도를 낮춘다.
- 지도 로딩/에러/성공 3단계 상태 표시(오늘 세션에서 만든 `complex-map-status` 처리)는 새 레이아웃
  안에서도 그대로 유지한다.
- 오피스텔 필터 UI 자리(향후 확장 지점)는 사이드바 상단, 행정동 좁히기 옆에 **비활성화된(disabled)
  드롭다운 하나**로 자리만 남긴다 — 옵션은 "아파트"만 선택된 채 고정, 클릭해도 아무 동작 없음.
  실제 오피스텔 옵션·기능은 별도 스펙에서 이 자리를 활성화하는 방식으로 넣는다.

### 3.3 사이드바 단지 목록

- `ComplexList.tsx`를 사이드바 폭에 맞는 compact 카드 스타일로 재조정한다(로직은 그대로, 시각적
  밀도만 조정).
- 목록 항목을 클릭하면 지도에서 해당 마커로 이동/강조하는 상호작용은 **이번 스펙 범위 밖**이다(있으면
  좋지만 필수 아님 — 계획 단계에서 시간 여유에 따라 Nice-to-have로 표시).

### 3.4 등기부등본 문진(`RightsCheck`) 제거

사용자 결정: 이 문진은 이번 개편에서 **완전히 제거**한다. 나중에 별도의 "등기부 분석 도구"로 다시
만들 계획이다 — 이번 스펙의 범위가 아니다.

  블록을 지운다. 관련 코드를 코드베이스에서 완전히 삭제한다 — 나중에 별도 도구로 다시 만들 때 새로
  설계하는 편이 낫다(반쯤 죽은 코드로 남겨두지 않는다). 확인한 삭제 대상(계획 단계에서 다시 한번
  각 파일의 실제 참조를 확인하고 확정):
  - `src/components/RightsCheck.tsx` / `.test.tsx`

  - `src/lib/deungi/`(디렉터리 전체 — `index.ts`, `rules.ts`. 다른 어디서도 import되지 않음, 확인함)

  **삭제하면 안 되는 것** (이름이 비슷해 보이지만 무관):

  축은 영구히 "확인 안 함"으로 표시된다 — 이 컴포넌트는 이미 "축 하나를 못 봤으면 그 사실을 숨기지
  않는다"는 원칙으로 설계돼 있어 코드 변경 없이도 이 상태를 정확히 그린다. 나머지 세 축(구매유형별
  금융·호가위치·입지사실)은 지금처럼 동작한다.
- **작은 카피 점검이 필요하다.** 권리분석 축의 "아직 보지 않았어요"류 문구가 "이 페이지 안에서 곧
  볼 수 있다"는 인상을 준다면(현재 문구를 구현 시 다시 확인), "등기부 분석은 별도 도구로 준비 중이에요"
  처럼 이 화면에서 다시 나타나지 않는다는 게 분명하도록 다듬는다. `src/state/useDiagnosisSummary.ts`,
  `src/components/DiagnosisSummary.tsx`의 문서 주석(`rights`가 "실질적으로 거의 언제나 값이 있다"고
  적힌 부분)도 더는 사실이 아니므로 갱신한다.
- 인쇄 관련: `RightsCheck`가 인쇄에서 강제로 펼쳐지던 `<details>` 처리(`::details-content` 규칙)는
  `RightsCheck` 자체가 사라지므로 자동으로 함께 없어진다 — 별도 정리 불필요.

## 4. 지도 마커 — 가격 항상 표시

### 4.1 마커 내용

- 현재: 클릭해야 InfoWindow 팝업으로 이름·평형별 범위·거래건수가 뜬다.
- 변경: 마커 자체에 **면적(대표 평형) + 가격 범위**를 항상 표시한다. 예: `"34평 11.6~12.6억"`.
- 대표 평형 선택 규칙: 그룹(같은 `complexKey`) 안에서 거래건수가 가장 많은 평형을 대표로 삼는다
  (동률이면 첫 번째). 나머지 평형 정보는 지금처럼 클릭 팝업에 남는다.
- 클릭 시 팝업 동작은 바꾸지 않는다 — 이미 검증된 `groupByComplex` + `escapeHtml` 로직을 그대로
  재사용한다.

### 4.2 구현 메커니즘

- Naver Maps `Marker`의 `icon: { content: "..." }` 옵션으로 커스텀 HTML 마커를 그린다(단순 핀 아이콘
  대신).
- 마커 라벨에 들어가는 모든 단지 유래 텍스트(평형, 가격, 거래건수)는 기존 `escapeHtml` 헬퍼를 거친다
  — 새 XSS 표면을 만들지 않는다.
- 가격 구간별 배경색(§1.4)은 이 커스텀 마커 HTML의 배경색으로 적용한다.

## 6. 테스트 전략

- **색상 대비**: 새 safe/caution/danger 값의 대비율을 계산하는 스크립트 또는 수기 계산 결과를
  구현 보고서에 남긴다(기존 관행).
- **마커 라벨 이스케이프**: `ComplexMap.test.tsx`에 커스텀 HTML 마커 라벨에도 `escapeHtml`이
  적용되는 회귀 테스트를 추가한다(기존 InfoWindow 팝업 테스트와 같은 패턴).
- **대표 평형 선택 로직**: 여러 평형 중 거래건수 최다 평형이 마커에 뜨는지 단위 테스트로 검증한다.
- **인쇄 동기화**: `scripts/printCss.test.ts`가 새 요소 추가 후에도 여전히 통과하는지 확인한다.
- **시각적 검증**: 자동 테스트로 색상·레이아웃이 "Seline답게 보이는지"는 검증할 수 없다 — 로컬
  브라우저(`npm run dev:full`)에서 직접 확인하는 수동 스모크 테스트가 필수다(오늘 세션에서 이미
  이 방식으로 지도 기능을 검증한 전례가 있다).
- **회귀 방지**: `npx vitest run` 전체 스위트와 `npm run typecheck`가 각 태스크 후 계속 깨끗해야
  한다 — 특히 색상 변경이 텍스트 콘텐츠 기반 어서션(`getByText` 등)을 깨뜨리지 않는지 주의한다.
- **`src/App.test.tsx`도 RightsCheck 제거의 영향을 받는다** — 등기부 문진을 채우거나 검증하는 기존
  테스트 케이스(있다면)는 지우고, `DiagnosisSummary`가 권리분석을 "확인 안 함"으로 그린다는 새 기대를
  추가한다.
