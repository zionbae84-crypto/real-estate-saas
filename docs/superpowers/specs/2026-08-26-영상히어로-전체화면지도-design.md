# 영상 히어로 + 전체화면 지도 — 구조·디자인 기준

> 이 문서는 사용자가 승인한 클릭 가능한 프로토타입을 기준으로 삼는다. 프로토타입에서
> 확정된 값(색·글꼴·간격·구조)은 여기 옮겨 적었고, 구현은 이 값을 그대로 쓴다.

## 왜 바꾸는가

직전 개편(Seline 팔레트)은 여백이 넓은 마케팅 페이지용 스타일이라, 숫자와 경고가
촘촘한 이 앱에서는 위계가 눌리고 훑기 어려웠다. 사용자 평가: "색이 너무 단조롭고,
불편하고 알아보기 어렵다", "AI 티가 많이 난다".

두 가지를 바꾼다.

1. **화면 구조**: 세로로 긴 한 페이지 → **두 화면**. 영상 배경 위 입력 화면, 그리고
   입력을 마치면 전환되는 전체화면 지도(좌측 사이드바 + 지도).
2. **시각 언어**: 팔레트를 배경 영상에서 뽑는다. 영상 평균색이 `rgb(104,117,132)`인
   한강 안개 톤이라, 중립색을 그 계열로 두고 강조색은 파랑을 피한다(영상 위에서
   묻힌다). 금액은 황동색 하나로 통일해 "돈"과 "설명"을 가른다.

## Global Constraints (깨면 안 되는 것)

- **단일 "적정가"를 절대 내지 않는다.** 지도 마커·목록·상세 어디에서도 범위
  (`minPrice`~`maxPrice`)로만 표기한다. 감정평가법 관련 제약이라 협상 대상이 아니다.
- **재무정보는 브라우저를 벗어나지 않는다.** `src/no-network.test.ts`가 `src/`를
  스캔하며 예외 파일은 정확히 둘(`src/lib/regionQuery.ts`, `src/lib/loadNaverMaps.ts`)이다.
  영상·폰트는 전부 로컬 번들이어야 한다.
- **SEED Design 상호작용 컴포넌트는 재구현하지 않는다** — 체크박스·슬라이더·텍스트필드·
  액션버튼. 색만 CSS 변수로 바꾼다.
- **계산 로직은 손대지 않는다.** `useAffordability`, `buildComplexList`,
  `useProfileForm`, `useRegionComplexes`, `useComplexCoordinates` 및 그 조건들.
  이번 작업은 **어디에 무엇을 그리는가**만 바꾼다.
- **`App.tsx`의 조건부 렌더링에는 여섯 번 반복된 버그 이력이 있다** — 한 축의
  "모름/비어 있음"이 다른 축의 기본값으로 조용히 흡수되는 형태. 조건을 옮길 때
  각 빈 상태가 여전히 **자기 원인**을 말하는지 확인한다.
- **인쇄가 깨지면 안 된다.** `src/print/hiddenInPrint.ts`의 `PRINT_HIDDEN_SELECTORS`와
  `src/styles.css`의 `@media print`가 동기화돼야 하고(`scripts/printCss.test.ts`가 검사),
  `MUST_SURVIVE_PRINT_CLASSES`의 내용은 잘리지 않아야 한다.
- **시/군/구는 필수, 동은 옵션**(기본값 "전체" = 구 전체 결과).

| 토큰 | 값 |
|---|---|
| `--safe` | `#4c9d7a` |
| `--warn` | `#c98a3c` |
| `--risk` | `#c4574f` |

밝은 면 위 태그:
- 안전: 글자 `#1d5c43` / 바탕 `#dff0e8`

4.5:1, 큰 굵은 글자는 3:1 기준.

## 2. 타이포그래피

- **제목**: 명조체. 부동산·건축 쪽 문법이지 SaaS 랜딩 문법이 아니다.
- **본문·데이터**: 고딕(현재 Pretendard 유지).
- 숫자는 `font-variant-numeric: tabular-nums`.
- 라운드는 거의 0 — 둥근 카드에 가두지 않는다.
- 가운데 정렬 없음. 왼쪽 축으로 미는 비대칭 구성.

명조체는 로컬 번들이어야 한다(외부 CDN 금지). `pretendard`처럼 npm으로 받을 수 있는
한글 명조를 찾거나, 시스템 명조 스택으로 대체한다 — 구현 시 판단하고 보고한다.

## 3. 화면 1 — 영상 위 입력

```
┌──────────────────────────────────────────────┐
│ [전체 화면 영상, object-fit: cover, 무음 루프] │
│ ┌──────────────┐                              │
│ │ 스크림(좌→우   │                              │
│ │  어두움→투명)  │      영상이 보이는 영역        │
│ │              │                              │
│ │ 작은 라벨      │                              │
│ │ 큰 제목(명조)  │                              │
│ │ 한 줄 설명     │                              │
│ │ ─ 입력들 ─    │                              │
│ │ 현금  [    ]  │                              │
│ │ 연소득 [    ] │                              │
│ │ 주택  ○ ○     │                              │
│ │ 지역  [▾][▾]  │                              │
│ │ [ 보기 → ]    │                              │
│ │ 개인정보 고지   │                              │
│ └──────────────┘                              │
└──────────────────────────────────────────────┘
```

- 그리드 `minmax(420px, 44%) 1fr`. 900px 아래에서는 1열.
- 영상: `autoplay muted loop playsinline`, `poster`로 정지 이미지 지정(첫 프레임 전
  빈 화면 방지). 자동재생이 막히면 poster가 그대로 보이면 되므로 별도 처리 불필요.
- 스크림: `linear-gradient(100deg, rgba(13,19,25,.95) 0%, rgba(13,19,25,.86) 34%,
  rgba(13,19,25,.34) 62%, rgba(13,19,25,.30) 100%)` 위에
  `linear-gradient(to top, rgba(13,19,25,.6) 0%, transparent 40%)`.
- **입력은 상자가 아니라 밑줄이다.** 서류를 채우는 느낌. 포커스 시 밑줄이 황동색.
- 입력 아래에 즉시 환산값을 황동색으로 보여준다(`20000` → `2억원`).
- 주택 보유는 세그먼트 두 개(테두리 공유, 선택된 쪽만 밝은 바탕에 어두운 글자).
- 입력 영역이 세로로 넘치지 않게 한다 — `justify-content: safe center` + `overflow-y: auto`.
  (프로토타입에서 실제로 넘쳐서 상단이 잘리는 문제를 겪었다.)

기존 컴포넌트 배치: `PurchaseTypeSelect`, `ProfileForm`, `RegionSelect`가 이 화면에
들어간다. 컴포넌트의 로직·prop은 그대로 두고 이 화면의 시각 언어에 맞춰 스타일만
입힌다.

## 4. 화면 2 — 전체화면 결과

```
┌──────────────────────────────────────────────────────┐
│ 살수있는집 │ 현금 2억 │ 연소득 6,000만 │ 한도 3억2,090만 │ 강남구 │ [인쇄] [다시] │
├────────────┬─────────────────────────────────────────┤
│ 살 수 있는  │                                          │
│ 단지        │                                          │
│ ─────────  │             지 도 (전체)                  │
│ 유형 ▾ 동 ▾ │                                          │
│ ─────────  │        [마커: 면적 가격범위]               │
│ 단지 행     │                                          │
│ 단지 행     │                                          │
│ 단지 행 ◀선택│                       [범례]              │
└────────────┴─────────────────────────────────────────┘
```

- `#result`는 `position: fixed; inset: 0; display: grid; grid-template-rows: auto 1fr`.
- `.stage`는 `grid-template-columns: 372px 1fr` **그리고
  `grid-template-rows: minmax(0, 1fr)`**.
  ⚠ 행을 `auto`로 두면 지도(자식이 전부 absolute라 내재 높이 0)가 높이를 못 받아
  타일이 안 뜬다. 프로토타입에서 실제로 겪은 버그다.
- ⚠ **네이버 SDK가 지도 컨테이너에 `position: relative`를 인라인으로 덮어써서
  `inset: 0`이 무력화된다.** 컨테이너에 `width: 100%; height: 100%`를 함께 줘야 한다.
  이것도 프로토타입에서 겪은 버그다.
- 페이지 자체는 스크롤하지 않는다(`body { overflow: hidden }`). 사이드바 목록만 스크롤.
- 900px 아래: 1열, 지도 위 / 목록 아래(`grid-template-rows: minmax(0,1fr) minmax(0,1fr)`).

### 상단바
- 좌: 서비스 이름(명조).
- 중: 요약 항목들 — 라벨(작고 자간 넓게, `--on-sheet-faint`) + 값(굵게). **한도**는
  황동색(`--brass-ink`)이고 **누르면 예산 상세 패널이 열린다.**
- 우: `인쇄` / `조건 다시 넣기`.

### 사이드바
- 헤더: "살 수 있는 단지" + "OO구에서 N곳 · 최근 6개월 실거래가"(N은 황동색).
- 필터: 매물 유형(비활성, 아파트 고정) / 행정동.
- 목록: 행마다 [단지명 + 면적·동] / [가격 범위(황동)] / [거래 N건] / [부담 태그].
  선택된 행은 왼쪽에 황동 표시선 + 옅은 바탕.
- **행을 누르면 사이드바가 단지 상세로 전환된다**(목록 ↔ 상세). 상세 안에 진단 종합이
  들어간다. 상세에서 목록으로 돌아가는 버튼 필요.

### 지도
- 마커는 지금과 같이 면적 + 가격범위 + 거래건수를 항상 표시.
- ⚠ **마커 색의 뜻이 바뀐다**: 가격대(싸다/비싸다)가 아니라 **부담 수준**
  (대출 없이 / 대출 필요)이다. 목록의 태그와 뜻이 같아져서 지도와 목록이 같은 말을 한다.
  기존 `priceTiers`(3분위)를 부담 기준 2분류로 바꾼다.
- 마커 상한(현재 30개)과 "N개 더 있어요" 문구는 유지한다.
- 좌측 하단에 범례: 무엇이 어떤 색인지.
- 목록 행 ↔ 마커는 양방향으로 연결된다(행 클릭 → 지도 이동 + 마커 강조, 마커 클릭 →
  행 선택 + 스크롤).

## 5. 기존 기능의 새 자리 (사용자 확정)

| 기능 | 새 자리 |
|---|---|
| 예산 상세 (대출 한도 4종, 부대비용, 정책대출, 슬라이더, 안전선) | 상단바의 "한도" 클릭 → 펼침 패널 |

## 6. 인쇄

전체화면 구조라 "페이지를 그대로 인쇄"가 성립하지 않는다. 인쇄 시에는 화면 레이아웃을
풀고(`position: fixed` 해제, 사이드바 스크롤 해제, 지도 숨김) 지금과 같은 세로 문서로
흐르게 한다. `PrintSummary`가 계산 전제를 종이에 남기는 역할은 그대로다.

`.region-results-sidebar`가 인쇄에서 잘리던 버그의 교훈: **`overflow`/`max-height`
제약을 건 요소는 반드시 `@media print`에서 풀어야 한다.** 새로 만드는 스크롤 영역
전부에 같은 처리가 필요하다.

## 7. 이번 범위 밖

- 오피스텔 데이터 연동 (별도 프로젝트, 필터 자리만 유지)
- 카피 축소·톤 변경 (별도 프로젝트)
- 영상 파일 압축 — 현재 20MB(1920×1080, 28.7초)로 리포지터리에 그대로 들어간다.
  배포 전에 2~4MB로 재인코딩해야 한다. 이 환경에 ffmpeg가 없어 이번엔 못 한다.
