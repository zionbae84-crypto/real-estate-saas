# 네 질문으로 줄이기 — 설계

> **갱신(2026-08-27):** 사용자가 "연소득은 입력하게 해줘"라고 해서 연 소득이
> 입력으로 돌아왔다. 질문은 셋이 아니라 **넷**이다. 그 결과 DSR·DTI 축을
> 그대로 쓸 수 있게 되어, 아래 §3의 위험이 통째로 사라졌다.

> 사용자 지시 원문:
> "여기서 제시했던 html이 내가 원한거고 지금은 너무 복잡해졌어.
> 딱 나 얼마있어, 어디 살고 싶어, 어느 평형대를 찾고있어 하면 다음 페이지에서
> 지도에 추천물건을 보여주고, 추천물건 입력시 간략한 취득시 발생하는 비용,
> 대출 받을시 필요한 원리금을 보여줄수 있는 구조로 만들어줘.
> 더 필요한 부분은 계속 추가해갈께"

## 0. 무엇이 문제였나

**색이 아니라 양이다.** 사용자가 승인했던 프로토타입은 지금과 **같은 팔레트**
(영상 배경 + 슬레이트 블루 + 금액에 황동)였다. 그 사이에 화면이 무거워졌다.

그러므로 **팔레트·폰트·두 화면 구조는 그대로 둔다.** 이 작업은 **덜어내는
작업**이다. 스타일을 새로 만드는 작업이 아니다.

`DESIGN.md`(사용자가 첨부한 shadcn 계열 스타일 가이드)는 **배치 규율만** 빌려
쓴다 — Stat Block(라벨 작게 위, 값 크게 아래, 왼쪽 정렬), Card, 배지, compact
밀도, 본문 14px 하한. **색은 빌려오지 않는다.**

## 1. 앱이 무엇이 되는가

```
화면 1 — 네 가지만 묻는다
   ① 얼마 있어?      현금
   ② 연 소득은?       세전 연 소득  ← 사용자 요청으로 유지
   ③ 어디 살고 싶어?  광역단체 + 시군구
   ④ 어느 평형대?     전용면적 범위
        ↓
화면 2 — 지도에 추천 물건
   좌측 사이드바 목록 + 우측 전체화면 지도
        ↓
물건을 고르면 — 두 가지만 답한다
   ① 살 때 드는 비용   취득세·법무비·중개보수 …
   ② 매달 나가는 돈    대출 원리금
```

## 2. 화면 1에서 없애는 것

**연 소득은 남는다**(사용자 요청). 그래서 DSR·DTI 한도 계산은 지금 그대로
동작한다 — 이 표에 없다.

| 없앤다 | 지금 무엇에 쓰였나 | 없앤 뒤 |
|---|---|---|
| 생애최초 주택 구입 | 정책대출 자격·LTV 우대 | 우대 없음으로 계산, 화면에 명시 |
| 기존 대출 | DSR 차감 | 없음으로 계산, 화면에 명시 |
| 무주택 / 유주택(주택 수) | LTV·정책대출 | 무주택 가정, 화면에 명시 |
| 규제지역 체크박스 | LTV 40% vs 70% | 지역 선택에서 **자동 판정**한다. 이미 지역 코드로 규제 여부를 아는 데이터가 있으면 그걸 쓰고, 없으면 비규제로 가정하고 화면에 명시한다 |
| 전용면적 "가정" | 부대비용 계산용 가정값 | **가정이 아니라 사용자가 고르는 필터가 된다**(③) |

**없앤 가정은 전부 화면에 남는다.** 이 저장소의 `AssumptionLine`이 존재하는
이유가 그것이다 — 숨긴 가정을 조용히 깔지 않는다. 다만 입력 화면이 아니라
**결과 화면의 접히는 자리**에 둔다.

## 3. 계산에서 바뀌는 것

연 소득이 남으므로 **DSR·DTI 축은 지금 그대로 살아 있다.** 한도 네 종
(LTV/DSR/DTI/정책대출)을 비교해 최솟값을 쓰는 구조를 건드리지 않는다.

바뀌는 것은 **없앤 입력들이 어떤 값으로 계산에 들어가는가**뿐이다:

| 없앤 입력 | 계산에 넘기는 값 | 화면에 적는 말 |
|---|---|---|
| 생애최초 | 아님 | "생애최초 우대는 빼고 계산했어요" |
| 기존 대출 | 없음 | "기존 대출이 없다고 보고 계산했어요" |
| 주택 수 | 무주택 | "무주택으로 계산했어요" |
| 규제지역 | 지역에서 자동 판정 | 판정 결과를 적는다 |

⚠ **이 저장소는 "한 축의 모름이 다른 축의 기본값으로 흡수되는" 버그를 여섯 번
반복했다.** 위 값들은 "모른다"가 아니라 **"이렇게 가정했다"**이고, 그 차이가
화면에 보여야 한다. 조용히 기본값으로 깔지 마라 — 각 항목이 `AssumptionLine`에
자기 문장으로 남는다.

**계산 로직 자체(`src/lib/finance/`)는 손대지 않는다** — 무엇을 넘기는지만 바꾼다.

## 4. 화면 1 — 네 질문

영상 배경·스크림·팔레트 **그대로**. 카드 하나에 네 줄.

1. **얼마 있어요?** — 현금. 지금의 `MoneyInput` 그대로.
2. **연 소득은요?** — 세전 연 소득. 지금의 `MoneyInput` 그대로.
   DSR 한도가 여기서 나온다.
3. **어디서 찾을까요?** — 광역단체 + 시군구. 지금의 `RegionSelect` 그대로.
   (시군구 필수, 동 좁히기는 결과 화면에 남긴다.)
4. **어느 평형대요?** — 전용면적 범위. **새로 만드는 유일한 입력이다.**

### 평형대 입력

칩 또는 세그먼트 형태로, 손으로 숫자를 치지 않게 한다.

| 라벨 | 전용면적 |
|---|---|
| 소형 | ~60㎡ |
| 중소형 | 60~85㎡ |
| 중형 | 85~102㎡ |
| 대형 | 102㎡~ |

- **복수 선택 가능**, 기본값은 전체 선택(=필터 없음).
- 85㎡ 경계는 **농특세가 붙는 경계**다. 이 경계를 지우지 마라 — 취득비용이
  실제로 달라지는 지점이고, 지금 코드가 이미 그 경계를 안다.
- 칸에 평(坪) 병기를 넣을지는 구현자 판단. 넣으면 `㎡`가 주(主)여야 한다.

네 개가 다 차면 조회 버튼이 활성화된다. **덜 찼으면 무엇이 모자란지 말한다**
(지금 그렇게 동작한다 — 커밋 `0a0ce54`. 그 동작을 지우지 마라).

## 5. 화면 2 — 지도와 목록

**구조 그대로.** 상단 요약 바 + 좌측 사이드바 + 우측 전체화면 지도.

덜어낼 것:

- **상단바 요약**: `현금 · 연 소득 · 실구매 가능 가격 · 지역`. 지금과 같다.
  "실구매 가능 가격"이 이 화면의 답이다.
- **예산 상세 패널**은 남기되 내용을 줄인다 — 없앤 가정들(§2)이 여기 들어간다.
- 목록 행: 단지명 · 평형 · 법정동 / **가격 범위** / 등급. 지금과 같다.
  **단일 적정가는 절대 내지 않는다**(변경 없는 전역 제약).

## 6. 물건을 고르면 — 두 가지만

지금의 `ComplexDetail`이 무겁다. **두 블록으로 줄인다.**

`DESIGN.md`의 **Stat Block** 배치를 쓴다: 라벨 12px 위, 값 24~30px/600 아래,
**왼쪽 정렬**. 지금처럼 값이 어정쩡하게 들여쓰기되지 않게 한다.

### ① 살 때 드는 비용

가로 그리드로 나란히. 합계를 크게, 내역은 접어서.

```
살 때 드는 비용
1,936만 4,212원          ← 크게, 황동

취득세   1,320만원    법무비   85만원
중개보수  520만원     기타     11만원   ← 접힌 자리
```

- 전용면적 85㎡ 초과면 농특세가 붙는다 — 그 사실을 한 줄로 말한다.
- 지금의 `CostBreakdown` 계산은 그대로. **배치만 바꾼다.**

### ② 매달 나가는 돈

```
매달 나가는 돈
187만원                  ← 크게, 황동
대출 3억 2,000만원 · 30년 · 연 4.2% 가정
```

- 금리·기간은 **가정이고 화면에 적는다.** 숨기지 않는다.
- 이 금액이 소득 대비 어느 정도인지(상환부담률)는 지금 계산이 이미 낸다.
  **한 줄로만** 덧붙인다 — 별도 지표 블록으로 키우지 않는다.
- 현금이 매매가를 넘어 대출이 필요 없으면 **"대출 없이 살 수 있어요"**라고
  말하고 0원을 크게 찍지 않는다. 이 저장소의 규칙이다 — 맨숫자 0은 답의 모양을
  한 거짓말이다.

### 그 외 상세 항목

`LocationFacts`(역·학교), `PriceCheck`(호가 위치)는 **지우지 말고 접어 둔다.**
사용자가 "더 필요한 부분은 계속 추가해갈께"라고 했다 — 지금 지우면 되살리는
비용이 크다. 기본은 접힘, 제목만 보인다.

## 7. 변하지 않는 것

- 팔레트·폰트·영상: **그대로**. 이번 작업에서 색을 바꾸지 마라.
- 단일 "적정가"를 절대 내지 않는다 — 마커·목록·상세 어디서도 범위로만.
- 재무정보는 브라우저를 벗어나지 않는다. `src/no-network.test.ts`의 예외는 둘.
- SEED 상호작용 컴포넌트를 재구현하지 않는다.
- 계산 로직(`src/lib/finance/`)은 손대지 않는다. **무엇을 넘기는지만 바꾼다.**
- 본문 4.5:1 / 큰 굵은 글자 3:1. 새로 만드는 평형대 칩도 실측한다.
- 인쇄가 깨지면 안 된다. `PRINT_HIDDEN_SELECTORS` ↔ `@media print` 동기화,
  `MUST_SURVIVE_PRINT_CLASSES` 내용은 잘리지 않는다.
  `overflow`/`max-height`를 건 요소는 반드시 `@media print`에서 푼다.
  (인쇄 **버튼**은 없앴지만 Cmd+P는 계속 동작해야 한다.)
- **빈 상태는 자기 원인을 말한다.** 여섯 번 반복한 실패다. 입력이 셋으로 줄면
  빈 상태의 원인도 줄어든다 — 하지만 새 원인이 생긴다: **"그 평형대에 매물이
  없어요"**와 **"그 지역에 거래가 없어요"**와 **"예산으로는 못 사요"**는
  서로 다른 말이다. 셋이 섞이지 않게 한다.

## 8. 레이아웃 함정 (그대로 유효)

1. `.region-results-grid`의 행은 `minmax(0, 1fr)`. `auto`면 지도 높이가 0이 된다.
2. 네이버 SDK가 지도 컨테이너의 `position`을 인라인으로 덮으므로 `.complex-map`은
   `width/height: 100%`로 칸을 채운다.
