# 색·모션·말투 설계

**작성일:** 2026-08-23
**상태:** 승인됨
**선행:** SEED Design 도입, UX 단순화 — 둘 다 main

## 1. 왜 하는가

화면이 단조롭고, 말투가 섞여 있다.

**말투:** 최근에 쓴 가정 문구는 해요체인데("규제지역으로 계산했어요… 눌러서 바꾸세요") 결과·경고는 합니다체다("상환 능력(DSR)에 **걸렸습니다**", "현금이 더 **필요합니다**"). 한 화면 안에서 두 목소리가 난다.

**색:** 이 앱에는 이미 안전 등급(`safe`/`caution`/`danger`)이 있는데 배지 하나에만 쓰인다. 나머지 화면은 의미와 무관하게 회색이다.

**모션:** 없다. 값이 바뀌어도 화면이 끊기듯 갈린다.

## 2. 원칙

**색은 장식이 아니라 의미의 반복이다.** 새로운 정보를 색으로만 말하지 않는다 — 이미 글자로 말한 것을 한눈에 읽히게 거든다.

**친근한 것과 무른 것은 다르다.** 이 제품의 일부 문장은 사용자를 멈춰 세우는 것이 일이다. 따뜻하게 말하되 짧게 끊고 에둘러 말하지 않는다.

## 3. 색

SEED가 이미 싣고 있는 의미별 토큰을 쓴다. **hex를 새로 만들지 않는다** — 명도 단계와 라이트/다크 값이 검증돼 있고, 브랜드 재정의(`src/seed-brand.css`)와 같은 규율이다.

| 의미 | SEED 토큰 계열 | 쓰이는 곳 |
|---|---|---|
| 안전 | `positive` | 안전선, `safe` 등급 |
| 주의 | `warning` | `caution` 등급, **고치면 숫자가 내려가는** 가정 |
| 위험 | `critical` | `danger` 등급, 경고, "안전한 가격 없음" |
| 브랜드 | `brand`(blue) | 최대 가격, 누를 수 있는 것 |
| 중립 | `neutral` | 본문, 보조 설명 |

가정 문구 셋 중 `warning`을 받는 것은 **기존 부채 하나뿐이다.** 나머지 둘(규제지역·전용면적)은 고치면 숫자가 올라가므로 중립으로 둔다. 이 구분이 이 화면에서 색이 하는 일의 전부다 — "고치면 손해 볼 수도 있는 것"과 "고치면 이득인 것"을 한눈에 가른다.

### 색만으로 의미를 전달하지 않는다

등급·경고는 **항상 글자로도** 말한다. 색각 이상 때문이기도 하지만 더 큰 이유는 **이 제품이 경고를 놓치면 안 되기 때문**이다. 색이 안 보이는 환경(고대비 모드, 흑백 인쇄, 색각 이상)에서 경고가 사라지면 그건 우리가 피하려는 실패 그 자체다.

`data-level` 같은 속성으로 등급을 표현하고 CSS가 색을 입히되, 텍스트 라벨을 없애지 않는다.

### 대비

`brandSolid` 계열의 흰 글씨 대비는 약 2.9:1로 WCAG AA(4.5:1) 아래다. SEED 기본 carrot도 2.94:1이라 우리 재정의가 만든 문제가 아니다. **이번 작업에서 색을 넓게 쓰므로, 새로 색을 입히는 곳마다 전경/배경 조합의 대비를 확인하고 부족하면 기록한다.** 조용히 넘기지 않는다.

## 4. 모션

상태가 **바뀔 때만** 쓴다. 가만히 있는 것은 움직이지 않는다.

- 결과 숫자 갱신
- 접기/열기
- 가정 항목을 눌러 편집기가 열릴 때
- 등급 색 전환

SEED의 모션 토큰을 쓴다: `--seed-duration-*`, `--seed-timing-function-enter` / `-exit`. 값을 직접 정하지 않는다.

### 숫자에 카운트업을 넣지 않는다

금액이 굴러 올라가면 게임처럼 보이고, 무엇보다 **읽을 수 있는 순간이 늦어진다.** 사용자가 기다려야 하는 숫자가 아니다. 값 자체는 즉시 바뀌고, 바뀌었다는 사실만 짧게 표시한다.

### `prefers-reduced-motion`

존중한다. 모션을 끈 사용자에게는 전환 없이 즉시 바뀐다. **이건 선택이 아니라 접근성 요구사항이다** — 전정기관 장애가 있는 사용자에게 모션은 불편이 아니라 증상을 유발한다.

## 5. 말투

**해요체로 통일한다.** 경고는 짧게 끊고 에둘러 말하지 않는다.

| 지금 | 바꿀 방향 |
|---|---|
| "상환 능력(DSR)에 걸렸습니다" | "소득이 한도를 정했어요" |
| "이것은 빌릴 수 있는 한계이지 무리하지 않는 선이 아닙니다" | "이건 빌릴 수 있는 한계예요. 무리 없는 선은 따로 있어요." |
| "대출로는 늘릴 수 없습니다 — 현금이 더 필요합니다" | "대출로는 못 늘려요. 현금이 더 있어야 해요." |
| "무리 없이 살 수 있는 가격대가 없습니다" | "지금 조건으론 무리 없는 가격대가 없어요." |
| "숫자로 읽을 수 없습니다" | "숫자로 읽을 수 없어요" |
| "계산 중 문제가 발생했습니다" | "계산하다 문제가 생겼어요" |

### 지키는 규칙

- **이모지를 쓰지 않는다.** 안 어울려서가 아니라, 경고 옆 이모지가 경고를 장식으로 만들기 때문이다.
- **숫자와 단위는 부드럽게 만들지 않는다.** "4억 7,610만원"은 그대로다. 금액을 "약 4.8억쯤"으로 바꾸지 않는다 — 이 앱에서 정확한 숫자는 친근함보다 우선한다.
- **도메인 용어를 지우지 않는다.** DSR·LTV는 그대로 두되 괄호로 풀어 쓴다. 사용자가 다른 곳에서 다시 만날 단어다.
- **경고를 질문으로 바꾸지 않는다.** "혹시 무리는 아닐까요?"가 아니라 "이건 빌릴 수 있는 한계예요."

### 예외

법적 면책 문구(`추정치이며 실제 대출한도는 금융기관 심사 결과에 따릅니다`)는 합니다체를 유지한다. 그 문장은 친근할 자리가 아니다.

## 6. 어떻게 지킬 것인가

말투 통일은 놓치기 쉽고 나중에 다시 섞인다. 새 화면을 만들 때마다 합니다체가 하나씩 섞여 들어온다.

**UI 문자열에 `합니다`/`습니다` 종결이 남아 있으면 실패하는 테스트를 둔다.** `scripts/`의 브랜드 토큰 가드와 같은 방식이다 — 소스에서 문자열을 뽑아 검사하고, 예외는 **한 곳에 모아** 각각 왜 예외인지 적는다.

예외 목록에 들어갈 것: 법적 면책 문구, 도메인 용어 안에 든 표현, 테스트 픽스처.

이 가드가 없으면 이번 작업은 한 번 정리하고 다시 섞이는 일회성 작업이 된다.

## 7. 하지 않는 것

- **레이아웃 변경** — 정보 위계는 UX 단순화에서 정했다. 이번엔 색·모션·말투만이다.
- **SEED 밖의 색** — 그라데이션·일러스트·커스텀 팔레트는 범위 밖이다.
- **다크 모드** — `colorMode: "light-only"`로 고정돼 있다. 켜려면 브랜드 토큰의 다크 블록부터 만들어야 하고 별도 작업이다.
- **화면 3~5(지역·단지)** — 별도 스펙이다. 이 작업이 먼저 끝나야 그 화면의 문구를 한 번만 쓴다.

## 8. 테스트

- 안전 등급이 `safe`/`caution`/`danger`일 때 각각 다른 의미 색이 적용된다
- **등급이 색과 함께 글자로도 표시된다** — 색 관련 속성을 지워도 등급을 읽을 수 있다
- `prefers-reduced-motion: reduce`에서 전환이 적용되지 않는다
- 숫자가 즉시 바뀐다(카운트업이 없다)
- **UI 문자열에 `합니다`/`습니다` 종결이 없다** — 예외 목록에 있는 것 제외
- 예외 목록의 각 항목이 실제로 소스에 존재한다(죽은 예외가 쌓이지 않게)
- 금액 표시 형식이 바뀌지 않았다

## 9. 완료 기준

- 화면 전체가 해요체다(예외 목록 제외)
- 위 표의 경고 문구 넷이 "따뜻하되 단호한" 형태로 바뀌었다
- 안전 등급이 의미 색으로 구분되고, 색 없이도 읽힌다
- 모션이 상태 전환에만 적용되고 `prefers-reduced-motion`을 존중한다
- 말투 가드 테스트가 있고, 합니다체를 되돌리면 실패한다
- 새로 색을 입힌 조합의 대비를 확인했고, 부족한 곳은 기록됐다
- 전체 스위트 통과, 타입체크 클린
