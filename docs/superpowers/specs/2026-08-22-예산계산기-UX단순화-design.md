# 예산 계산기 UX 단순화 설계

**작성일:** 2026-08-22
**상태:** 승인됨
**선행:** Plan C(예산 계산기 UI), 룰셋 2026-08 — 룰셋 작업이 먼저 끝나야 한다

## 1. 왜 하는가

지금 첫 화면이 여덟 가지를 묻는다. 그중 넷은 보통 사람이 답할 수 없다.

| 항목 | 왜 못 답하나 |
|---|---|
| 기존 부채 **연간 원리금** | 사람들은 "매달 얼마 나간다"를 안다. 연간 원리금 합계라는 말을 모른다 |
| 예상 **양도세** | 사실상 아무도 모른다 |
| **규제지역** 여부 | 정책 지정 상태를 알아야 답한다 |
| **전용면적 ㎡** | 집을 고르기 *전에* 묻고 있다 |

답을 못 하면 폼을 떠난다. 계산기가 아무리 정확해도 도달하지 못한다.

동시에 결과 영역은 여섯 컴포넌트를 한꺼번에 펼친다. 무엇을 먼저 봐야 하는지가 없다.

## 2. 원칙

**가정을 숨기되, 결과 옆에 문장으로 두고, 눌러서 고치게 한다.**

가정을 조용히 숨기면 우리가 "낙관적인 앱"이 된다. 이 제품은 사지 말아야 할 때를 말해주는 앱이므로, 유리한 가정을 소리 없이 깔 수 없다.

## 3. 첫 화면: 세 가지

**보유 현금 · 연 소득 · 생애최초 여부**

생애최초를 남기는 이유는 규제지역에서 LTV 40%와 70%를 가르는 값이기 때문이다. **한도가 30%p 흔들린다.** 누구나 1초에 답할 수 있어 비용이 거의 없다.

나머지 다섯은 첫 화면에서 사라진다.

## 4. 숨긴 가정과 그 방향

| 숨긴 항목 | 기본값 | 사용자에게 |
|---|---|---|
| 규제지역 | `true` — 규제지역으로 가정 (LTV 40%) | 불리 |
| 전용면적 | 85㎡ 초과 값 — 농특세가 붙는 쪽 | 불리 |
| 주택 보유 상황 | `무주택` | 해당 없음 |
| 기존 부채 | 0원 | **유리** ⚠️ |

전용면적 기본값은 룰셋의 `acquisitionTax.ruralTaxAreaThresholdSqm`(85)보다 **큰 값**이어야 한다. 숫자를 코드에 직접 박지 말고 그 룰셋 값에서 유도한다 — 임계값이 바뀌면 기본값도 따라가야 하고, 그러지 않으면 "불리한 쪽"이라는 성질이 조용히 뒤집힌다.

기존 부채만 방향이 반대다. 없는 빚을 지어낼 수 없다. 그래서 이 항목은 **문구로 반드시 보이게** 하고, 고치면 숫자가 내려가는 유일한 항목이라는 사실이 드러나야 한다.

나머지는 고치면 숫자가 **올라간다.** 추가 입력이 벌점이 아니라 보상이 되는 구조다.

### 가정 문구

결과 바로 아래에 한 줄로 둔다.

> 기존 대출 없음 · 규제지역 · 85㎡ 초과로 계산했습니다 — *고치기*

각 항목을 누르면 **그 항목만** 열린다. 폼 전체로 돌아가지 않는다. 사용자가 값을 넣은 항목은 문구에서 빠지고, 넣은 값이 그 자리에 보인다.

주택 보유 상황(갈아타기)은 문구에 넣지 않는다 — "무주택으로 계산했습니다"는 대부분의 사용자에게 잡음이다. 대신 별도 링크 하나로 갈아타기 경로에 들어가게 한다.

## 5. 물어보는 말을 바꾼다

기존 부채를 열었을 때 **"매달 나가는 대출금"** 을 묻고 12를 곱해 `existingDebtAnnualPayment`에 넣는다. 사람들이 실제로 아는 숫자다.

변환은 UI 층에서 한다. 엔진의 `BuyerProfile`은 그대로 둔다 — 재무 계산은 연간 기준이 맞고, 표현의 문제를 타입으로 끌고 들어가지 않는다.

## 6. 결과의 계단

지금은 `BudgetResult`가 `WarningList` → 가격 → `BindingExplainer` → `CostBreakdown` → `PolicyLoanList`를 한 번에 펼친다. 이걸 네 단으로 나눈다.

1. **최대 가격** — 크게
2. **무엇이 막았는지 한 줄** — `BindingExplainer`를 한 문장으로 줄인다
3. **안전선** — 최대 가격 **옆에 나란히**
4. **접힌 채로** — 부대비용 내역, 정책대출 목록, 상세 설명

경고(`WarningList`)는 접지 않는다. 경고는 접으면 안 되는 종류의 정보다.

3번이 이 제품의 정체성이다. 다른 앱은 1번에서 멈추고 그 숫자를 크게 보여준다. 나란히 두는 것은 "무리 없는 선"이 최대치와 **동등한 무게**를 갖는다는 뜻이다.

## 7. 안전선 계산 — 엔진에 없는 값

`calcSafetyScore(profile, rules, price)`는 **주어진 가격에서의** 안전도를 낸다. "안전을 유지하는 최대 가격"은 그 역함수이고 지금 엔진에 없다.

### 정의

`calcSafePrice(profile, rules)` — `calcSafetyScore(...).level === "safe"`를 유지하는 최대 매매가. 상한은 `calcAffordablePrice`의 결과다(살 수 없는 가격을 안전하다고 말할 수 없다).

### 구현 방침

**`calcAffordablePrice`의 구간 분할 이분 탐색 기계를 재사용한다.** 술어만 "현금으로 감당 가능"에서 "안전 등급 유지"로 바뀐다.

상환부담률은 대출액에 비례하고 대출액은 정책대출 절벽·캡 구간에서 불연속이므로, 단조성이 깨지는 지점이 `calcAffordablePrice`와 **정확히 같다.** 따라서 같은 `buildSearchSegments`를 쓴다. 두 탐색이 같은 절벽 목록을 공유해야 하므로, 절벽 계산을 한 곳에서만 하도록 보장한다.

### 경계 조건

- 가격 0에서는 대출 0 → 월 상환액 0 → 부담률 0 → 항상 "안전"이다. 그래서 안전선은 항상 0 이상이 나오며, "안전한 가격이 없다"는 상태는 존재하지 않는다.
- **안전선이 0원이면 그 숫자를 크게 보여주지 않는다.** "지금 소득으로는 무리 없이 살 수 있는 가격대가 없습니다"로 바꿔 말한다. 0원을 결과로 내미는 것은 정보가 아니라 조롱이다.
- 안전선이 최대 가격과 같으면(=최대치까지 전부 안전) 나란히 두 숫자가 같아 이상해 보인다. 이 경우 한 줄로 합쳐 "최대 가격까지 부담률이 안전 범위입니다"로 표시한다.
- 안전선은 `PRICE_STEP` 단위로 **내림**한다. 올림하면 안전하지 않은 가격을 안전하다고 말하게 된다.

## 8. 슬라이더

슬라이더는 유지하되 접힌 영역 바로 위로 내린다. 최대 가격과 안전선을 본 다음에 탐색하는 순서다.

슬라이더 눈금에 **안전선 위치를 표시**해, 끌면서 그 선을 넘는 순간이 보이게 한다.

## 9. 하지 않는 것

- **지역·단지 선택** — Plan B 데이터를 붙이면 지역 선택으로 규제지역 여부가, 평형 선택으로 전용면적이 자동으로 정해져 **가정 두 개가 사라진다.** 화면 3~5번 작업이라 이번 범위 밖이다.
- **엔진의 `BuyerProfile` 변경** — 월→연 변환은 UI 층에 둔다.
- **디자인 시스템·테마** — 구조와 정보 위계만 다룬다.
- **갈아타기 경로 재설계** — 링크로 진입하는 별도 경로로 유지한다. 양도세 입력 난이도는 이번에 풀지 않는다.

## 10. 테스트

- 첫 화면에 입력이 셋만 있다
- 현금·연소득만 넣으면 결과가 나온다 (생애최초 미선택 = false)
- 가정 문구가 실제 사용 중인 기본값을 반영한다 — 기본값을 바꾸면 문구가 따라 바뀐다(하드코딩된 문자열이 아니다)
- 가정 항목 하나를 열어 값을 넣으면 그 항목이 문구에서 빠진다
- 기존 부채를 넣으면 최대 가격이 **내려간다**
- 규제지역을 끄면(비규제) 최대 가격이 **올라간다**
- "매달 나가는 대출금"에 넣은 값이 엔진에는 ×12로 전달된다
- 안전선이 최대 가격을 넘지 않는다
- 안전선 가격에서 `calcSafetyScore`가 실제로 "안전"이고, 안전선 + `PRICE_STEP`에서는 아니다
- 안전선 0원일 때 숫자 대신 문장이 나온다
- 안전선 == 최대 가격일 때 합쳐진 한 줄이 나온다
- 경고는 접히지 않는다

## 11. 완료 기준

- 첫 화면 입력이 여덟에서 셋으로 줄었다
- 숨긴 가정이 모두 결과 옆 문구에 드러난다
- 가정 기본값이 기존 부채를 제외하고 전부 사용자에게 불리한 쪽이다
- 기존 부채 가정이 문구에 명시된다
- 안전선이 최대 가격과 나란히 표시된다
- 안전선 계산이 `calcAffordablePrice`와 같은 절벽 목록을 쓴다
- 전체 스위트 통과, 타입체크 클린
