# 확인이 필요한 규제값

이 앱의 규제·판정 수치는 전부 `rules/*.json`에만 있습니다. 코드에는 숫자가 없습니다.
아래는 **아직 근거 있는 출처로 확인되지 않았거나, 아예 계산에 들어 있지 않은 값**의 목록입니다.

각 항목은 독립적으로 채울 수 있습니다. 출처를 주시면 해당 룰셋 파일만 고치면 되고,
엔진을 함께 건드려야 하는 항목은 그렇게 표시해 두었습니다.

## C. 법정 기준이 아니라 우리가 정한 참고선 — 근거를 붙이면 좋은 것

이것들은 **고시된 기준이 존재하지 않습니다.** 실무 감각으로 둔 선이고, 룰셋 `_note`에 그렇게 적혀 있습니다.
바꾸실 때는 "왜 그 숫자인가"를 함께 남겨 주시면 됩니다.

## D. 데이터 자체의 한계 — 값을 채워서는 못 고치는 것

### D1. 실거래 집계에 층(floor)이 없습니다

같은 평형의 저층과 로열층이 한 범위에 섞입니다. 층 차이는 실무에서 흔히 5~15%로 말해지는데,
그래서 호가 판정의 최소 거래 건수(5건)와 "한참 위" 기준(20%)이 필요 이상으로 보수적입니다.

원본 API는 `floor`를 주는데 우리 집계가 버립니다. **재수집 없이 집계만 고치면 됩니다.**

### D2. 원본 API가 주는데 버리고 있는 필드

재수집이 필요합니다(API 키 필요, 36회 호출).

| 필드 | 쓸모 |
|---|---|
| `aptSeq` | **단지 고유 ID.** 지금의 이름 기반 키가 가진 과소·과대병합 문제가 사라집니다 |
| `landLeaseholdGbn` | **토지임대부 여부.** 권리분석의 "사면 안 돼요" 신호인데 지금은 사용자에게 물어서 받습니다 |
| `roadNm`, `jibun`, `umdCd` | 지오코딩 → 입지분석의 전제 |
| `floor` | D1 |

### D3. 판정 유보가 86.8%입니다

호가 위치 판정은 1,692개 평형 중 1,468개에서 유보됩니다.
최근 6개월 거래가 1건인 평형이 849개(50.2%), 범위가 한 점인 평형이 51.7%이기 때문입니다.

**이건 임계값을 낮춰서 고칠 수 없습니다.** 낮추면 줄어드는 것은 위험이 아니라 우리가 틀리는 것을
알아챌 기회입니다. 고치려면 대상 지역을 넓혀 거래 표본을 늘려야 합니다.
