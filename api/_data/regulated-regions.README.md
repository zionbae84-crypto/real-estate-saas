# 규제지역(투기과열지구·조정대상지역) 코드 — 출처와 갱신 방법

`regulated-regions.json`이 지역 조회 시 자동으로 LTV를 가르는 데이터의
유일한 출처다(`api/complexes.ts` → `api/_lib/handleComplexes.ts`
`resolveIsRegulated` → `src/App.tsx`의 useEffect → `isRegulatedArea` →
`src/lib/finance/loan-limit.ts`의 LTV 테이블 선택).

## 출처

국토교통부 보도참고자료, **"투기과열지구 및 조정대상지역 추가 지정"**
(배포 2026.6.30., 지정효력 발생 2026.7.1.). 사용자가 첨부한 PDF —
`(260630(보도참고) 투기과열지구 및 조정대상지역 추가 지정(주택정책과).pdf`.

이 문서의 참고2("투기과열지구 및 조정대상지역 현황")가 추가지정 후
(2026.7.1. 이후) 전체 목록을 표로 낸다:

- **서울 25곳** — 강남·서초·송파·용산(2017.8.3. 지정) + 나머지 21개 구
  (2025.10.16. 지정). 서울 전 자치구가 규제지역이다.
- **경기 15곳** — 수원(장안·팔달·영통)·성남(수정·중원·분당)·안양동안·
  과천·용인(수지·기흥)·광명·하남·의왕(2025.10.16. 지정) +
  **화성동탄·용인기흥·구리(2026.7.1. 신규 지정, 이 보도자료의 본문)**.

이 문서의 참고1은 투기과열지구와 조정대상지역의 지정 효과가 다르다는 것을
보여준다(조정대상지역: 대출+세제+청약, 투기과열지구: 대출+청약). **다만
이 앱이 계산하는 LTV(40%/0%, 무주택/유주택)는 참고1 표에서 둘을
구분하지 않고 "규제지역"으로 함께 묶여 있고**, 이 보도자료의 목록
자체도 두 지정을 같은 지역 40곳에 동시에 건다(투기과열지구 25+15곳과
조정대상지역 25+15곳이 정확히 같은 지역이다). 그래서 이 앱은 지금처럼
**단일 `isRegulatedArea` 불리언**으로 충분하다 — 둘을 나눠 재는
계산이 이 룰셋(2026-08)에 없다.

## regulated 코드 40개 — `data/legal-dong-codes.json`과 대조해 뽑았다

이름을 손으로 옮기지 않고, 이 저장소가 이미 갖고 있는 법정동코드
원천(`data/legal-dong-codes.json`, `sigunguName` 기준)에서 정확히 이
이름들과 매칭되는 5자리 코드를 하나씩 확인해 채웠다. 특히 아래처럼
**같은 시 안에서 일부 구만** 지정된 경우가 있어, 시 이름만 보고
전체를 넣으면 안 된다:

| 시 | 지정된 구 | 지정 안 된 구(포함하지 않는다) |
|---|---|---|
| 수원시 | 장안·팔달·영통 | 권선구 |
| 안양시 | 동안 | 만안구 |
| 용인시 | 수지·기흥 | 처인구 |
| 화성시 | 동탄 | 만세구·효행구·병점구 |

## nonRegulated는 비워 둔다 — 근거 있는 결정이다

이 보도자료는 **규제지역이 어디인지만** 말한다. "나머지 전부가
비규제지역"이라고 확언하려면 전국 나머지 시군구를 모두 나열해야
하는데, 그건 이 문서가 주는 근거를 벗어난 추정이다. 지어내지 않는다.

`App.tsx`의 지역 조회 useEffect가 이미 이 공백을 다루는 규칙을 정해
뒀다: `regulated`에도 `nonRegulated`에도 없는 지역은 `isRegulatedArea`를
**가정 상태(보수적으로 규제지역 취급)**로 되돌린다 — 그 지역이
실제로는 비규제라면 한도를 낮게 보여주는 실패 방향이라, 사용자에게
안전한 쪽이다. `nonRegulated`를 채우려면 이 보도자료와 같은 급의
근거(국토부 고시·보도자료)가 따로 필요하다.

## 갱신 방법

새 지정·해제 보도자료가 나오면:

1. 보도자료의 최신 전체 목록(추가지정 "후" 표)을 읽는다 — 이번처럼
   신규 지정분만 보고 기존 목록에 더하지 마라, 해제된 지역이 있으면
   전체 표를 다시 대조해야 놓치지 않는다.
2. 각 지역명을 `data/legal-dong-codes.json`에서 `sigunguName`으로
   찾아 5자리 코드를 확인한다(위 표처럼 시 이름만 보고 구를 전부
   넣지 않도록 주의한다).
3. `regulated-regions.json`의 `regulated` 배열을 그 코드 전체로
   교체한다(추가만 하지 않는다 — 해제된 지역은 빠져야 한다).
4. 이 문서의 "출처" 절을 새 보도자료로 갱신하고, 지정효력 발생일을
   적는다.
